# Hummingbird+ 对 KVmix FPGA 项目的启发与实施建议

日期：2026-10-16。适用对象：PC1、PC2、B。项目基线：方案 C、SmolLM-135M、RK3576J + PH1A90SEG324。

本文是论文阅读分析与候选优化建议，不改变现有协议、B/U/M 定义、模型或数值验收要求。文中明确区分论文报告、项目本地证据、计算推导和待验证建议；开放问题继续维护在 [UNKNOWNS](UNKNOWNS.md)。

## 1. 结论

这篇论文最直接的价值，是指导我们提高 Attention 数据通路对 DDR、片上缓存和 DSP 的利用率。建议继续推进当前 SmolLM-135M + KVmix 路线，优先吸收以下设计思想：

1. 通过性能计数定位实际瓶颈，再决定增加计算并行度还是优化存储访问。
2. 将 GQA 从共享 KV 存储进一步推进到组内共享数据流和并行计算。
3. 采用分块读取、缓冲和预取，让 DDR 访问与计算重叠。
4. 优化 softmax 遍历和归一化，同时保留独立的数值质量验证。
5. 将混合精度 KV 的读取、解包、反量化与 Attention 融合，减少额外 DDR 搬运。

推荐顺序：**当前功能 bit 实板单层对拍 → 性能计数 → 根据瓶颈优化 GQA/DDR → 同一计算通路上的 B/U/M 实验 → 多层与端到端验证。**

## 4. 五项具体启发

### 4.1 先定位瓶颈，避免把“KV 更小”直接当作“推理更快”

论文 §2.2 强调内存访问的重要性，同时指出 GQA 在上下文增大时也受计算能力影响。我们的当前实现具有明显的串行计算和握手开销，需要建立自己的性能模型。

本地 `attention.v` 中，QK 与 PV 都逐元素执行，乘法、累加各占一拍。仅这两部分的循环周期推导为：

```text
MAC 数 = QK + PV = 2 × Hq × D × T
周期数 = 2 × MAC 数 = 4 × Hq × D × T
Hq=9、D=64、T=64：147456 周期
133.333MHz 下：约 1.11ms / 层
```

这是结构推导，不是实测，也没有计入 KV 装载、softmax、状态切换和 PCIe 等待。它说明当前实现不能直接套用论文平台的“内存主导”判断。

建议增加以下计数或计时：

| 指标 | 用途 |
|---|---|
| AXI 读写握手字节数、事务数 | 验证实际流量、burst 长度和压缩收益 |
| AXI 等待/背压周期 | 区分 DDR 等待与下游消费过慢 |
| KV 装载、解包、转换周期 | 识别数据搬运和转换成本 |
| QK、softmax、PV 周期 | 判断应增加计算通道还是优化特殊函数 |
| Host 端传输、等待、完整单层时间 | 评价 PCIe 和调度开销 |
| 端到端 TPOT、TTFT | 验证整机收益，不只看 FPGA 内核 |

v2 当前 ATTENTION 帧为 H2C 1952B、C2H 1184B，30 层合计逻辑帧字节数为 `30 × (1952+1184) = 94080B/token`，不含 PCIe 底层额外开销。B/U/M 共用这一 wire profile；KV 压缩减少的是 FPGA 内部 KV 存储/DDR 流量，不会自行减小这些固定帧。

计时要明确边界：包含证据落盘的 runner RTT 与裸 DMA 延迟不能直接比较；重叠阶段不能简单相加为端到端时间。

### 4.2 从 GQA 存储共享推进到数据广播和组内并行

论文 §4.1、图 4 让多个查询头协同使用共享 K/V。SmolLM-135M 的映射是：

```text
Q0、Q1、Q2 → KV0
Q3、Q4、Q5 → KV1
Q6、Q7、Q8 → KV2
```

本地 `attention_engine.v` 已按 KV 头读取实际历史切片，避免为每个 Q 头重复读取完整 DDR 历史；`gqa_attention.v` 则缓存 K/V，逐头送入同一个单头 Attention 核。

候选优化：同组 K/V 块读取、转换一次，广播给三个查询头的计算通道，分别维护各头的分数、softmax 状态和输出累加器。

预期改善的是片上重复装载与串行计算时间。当前 DDR 读取已经复用，因此不能据此宣称 DDR 流量再下降三倍；完整单层或系统延迟也不能预设获得三倍加速。

可先比较少量并行 MAC lane 和三头协同方案，再按综合、P&R、供数能力及实测选择。当前 DSP 占用低是探索空间，不是可实现频率或线性加速的保证。

### 4.3 分块缓存、连续读取与预取

本地 `kv_store_axi.v` 每接收一个 128-bit 数据拍，锁存后用 8 个周期拆成 16-bit 数，在解包期间对 AXI 读通道施加背压。这种实现便于验证，但持续吞吐受拆包和下游消费速度限制。

可研究的组织方式：

```text
DDR burst → 缓冲区 A → 解包/反量化 → Attention
             缓冲区 B ← 预取下一块
```

以一个 KV 头、32 个 token、D=64 为例，FP16 K/V 块的净数据量为：

```text
K + V = 2 × 32 × 64 × 2B = 8192B
两块交替缓冲 = 16KiB 净数据
```

这个数字不含元数据、FIFO、查询、score/probability 和输出累加器，也不等于 TD 实际分配的 ERAM 容量。

实施时要同时考虑：

- 地址布局与读取方向一致，减少逐 token、逐头短事务；保留 4KiB 边界拆分。
- 缓冲可以吸收短期停顿；持续吞吐还需要解包、转换和计算匹配供数速度。
- 分块处理必须覆盖完整因果历史，不能只计算当前块；需要配套 score 缓存或经过验证的在线归约算法。
- 量化 group 边界、3-bit 打包边界与读取块边界可能不同，要明确 padding 和残组处理。
- 当前协议单请求在途、同 token 各层存在依赖。DDR 块预取不等于可以任意并行 30 层。

### 4.4 softmax 优化必须同步更新数值参考

论文 §4.1 使用 online softmax，将相关遍历从三遍减少到两遍；§5.2 使用 LUT 实现指数函数。我们的 exp LUT 方向与其一致。

本地实现仍对每个概率执行迭代除法。一个可单独评估的优化是：同一 softmax 行的分母只求一次倒数，再通过乘法生成概率；之后再考虑 online softmax 的两遍组织。

这两项是不同的候选优化。“一次倒数 + 多次乘法”是针对当前代码提出的建议，不应写成论文已经证明适用于我们数值格式的方案。

验证至少包括 RTL 与更新后的定点参考一致、与浮点 Attention 的误差、长短上下文及极值稳定性，以及真实模型质量。改变归一化方式会改变舍入和误差分布；论文的动态 12-bit 激活也不等价于我们的固定 Q8.8。

### 4.5 让 KVmix 压缩流直接进入计算

借鉴论文中量化数据、缩放和计算的紧密衔接，可以将我们的通路组织为：

```text
DDR 压缩 KV + 元数据
  → 读取层/块位宽与 scale、min
  → 解包、反量化
  → 共享 KV 数据流
  → QK / softmax / PV
```

尽量避免为计算把完整历史恢复为 FP16 后再写回 DDR，否则会增加流量并抵消部分压缩收益。

KVmix 还需要处理 K/V 不同分组方向、2/3/4-bit 打包、recent FP16 tail、tail 驱逐转量化以及元数据和状态的一致性。压缩收益应扣除元数据、对齐填充、残组和迁移开销。

值得验证的研究问题是：**混合精度节省的 DDR 流量能否超过解包、反量化和缓存管理新增成本？在相同 KV 字节预算下，是否比统一量化保持更好的模型质量？**

这是本项目可检验的研究方向，不代表已经证明性能收益或文献创新性。

## 5. 可借鉴程度与移植限制

| 方法 | 对本项目的建议 |
|---|---|
| GQA 数据广播、分块缓存、预取 | 优先借鉴，按 Smol 的 9/3 头结构和实际 DDR 行为设计 |
| DOT / AXPY 数据组织 | 借鉴计算和数据访问方向；PV 可研究按 token 读 V 向量并更新输出向量 |
| 时间上互斥的算子共享资源 | 依据实际占用分析；也要防止过度复用造成吞吐下降 |
| Online softmax、倒数复用 | 单独做数值和性能消融，再决定是否集成 |
| DSP48E2 打包、级联、内部 mux、双时钟 | 与 Xilinx 原语强相关，安路必须重新验证映射和时序 |
| 266/532MHz 运行方式 | 是论文实现条件，不是 PH1A90 可直接采用的频率目标 |
| 多 token processor 加速 prefill | 长期参考，需要 RK 调度、因果 mask 和数据接口共同设计 |
| 24GB 双通道内存、自研 PCB、MoE 全模型部署 | 作为架构背景，不改变当前板卡和冻结模型路线 |

论文中 Double Data Rate 的计算技巧指双速率计算安排，需结合上下文区分，不能与板载 DDR 存储器或其数据率混为一谈。

作者提供的 [llama-fpga 仓库](https://github.com/adamgallas/llama-fpga)可作为前作的数据通路学习材料。其 README 标注 DATE/ICCAD 2025，介绍 LLaMA2-7B、SpinalHDL 生成 Verilog 及 Xilinx 平台；不能直接视为 Hummingbird+ 的完整复现工程或可直接导入 TD 的安路实现。

## 6. 对照实验建议

把计算结构优化和量化策略优化分开验证，避免同时改变多个变量。

| 对照 | 保持一致的条件 | 主要问题 |
|---|---|---|
| 串行 Attention vs 少量并行 lane / GQA 组内协同 | KV 精度、输入、参考算法、计时边界 | 计算加速与资源代价 |
| 当前 DDR 访问 vs 分块预取 | 计算核心、KV 精度 | burst 效率、背压、重叠带来的收益 |
| 当前 softmax vs 倒数复用 / online softmax | 输入分数和共同质量门槛 | 周期、资源与数值误差的权衡 |
| B vs U vs M | RK 权重/计算、wire profile、FPGA 共享算术、数据集 | 存储、流量、性能和模型质量 |
| 同 KV 字节预算的统一量化 vs 层感知策略 | 包括元数据、padding、tail 的预算 | 精度分配本身的价值 |
| RK-only vs RK + FPGA | 相同模型、任务、质量要求和计时定义 | 包含通信后的系统收益 |

正式 U 仍为既定的 K2/V2 无 tail。同预算对照如需改变统一量化位宽或尾部设置，应另命名为消融配置，不暗改 U。对 M 可进一步做 tail-only、同字节随机层分配等消融，区分 recent tail 与重要性分配的贡献。

上下文按 64 → 128 → 256 逐档验证；当前功能 bit 的上限为 64，扩大参数后需要重新构建和验收。

建议记录：

- 正确性：每帧 CRC、seq/layer/position、输出定点对拍、有限值检查。
- 数值与模型：浮点 Attention 误差、PPL、next-token 一致率及生成样例。
- 存储与流量：KV 实际字节、元数据、tail/迁移字节、DDR 读写字节。
- 性能：FPGA 各阶段周期、单层延迟、端到端 TPOT/TTFT、重复次数和分位数。
- 硬件：LUT、ERAM、DSP、实际频率和时序报告；如测功耗，区分芯片估算与整板测量。

## 7. 推进顺序与协作建议

| 顺序 | 工作 | 建议协作 | 完成依据 |
|---|---|---|---|
| 1 | 完成现有功能 bit 的实板单层对拍 | B 核对 bit/DDR，PC2 执行传输，PC1 复核参考 | 真实板端输出和完整证据 |
| 2 | 增加性能计数、统一计时定义 | B 提供设备内计数，PC2/PC1 拆分 host 与端到端时间 | 能解释瓶颈的阶段数据 |
| 3 | 按瓶颈选择 GQA 并行或 DDR 分块优化 | B 主导 RTL，PC1 复核数值，PC2 回归接口 | 相同输入下正确、资源/时序通过、实测改善 |
| 4 | 在同一计算核心上集成并比较 B/U/M | B 管理布局/转换，PC1 固定策略与模型评测 | 存储、流量、质量和延迟的完整对照 |
| 5 | 扩展上下文、多层和整机测试 | 三方按板卡独占窗口协作 | 端到端质量、性能和稳定性 |

本文提供后续决策依据，不代替实测，不关闭现有 UNKNOWN，也不授权访问共享板卡或修改固定协议。协作与板上操作继续遵循 [COOPERATION](../pcie_contract/COOPERATION.md)。
